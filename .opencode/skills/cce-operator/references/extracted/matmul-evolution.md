# Matmul + ReLU 演进经验

设计多核、尾块、流水或融合时查阅。本文提炼历史开发记录，不依赖原算子目录。本文没有附带 Matmul 工程；仓库完整 CCE 接入参考见[SFA 导航](../repository-integration.md)。历史 C/V GM 交接曾在 dav-2201 验证，不能直接混用两种架构的接口与布局。

## 从正确性到并行

1. 单 tile 先独立验证 Cube 装载、转置、首次 MAD 初始化及写回。使用非对称输入和正负混合输出，避免全一输入掩盖布局错误。
2. 沿 K 维循环时首块初始化 L0C，后续累加；输出 tile 结束后，下一 tile 重新初始化。
3. 输出 tile 编为一维任务，第 g 组处理 g、g+groupCount 等任务。按设备核数与任务数选择组数，测试少任务、不整除及每组多任务。
4. 直接接收 NPU 输入和行步长，在设备搬运时处理布局与补零。K 尾块防止旧缓冲数据参与计算；输出边界须区分逻辑尺寸与物理对齐缓冲，不能以结果正确推断没有越界。
5. Torch 绑定使用输入设备当前流并保证异步资源生命周期，覆盖默认流、非默认流和带行间距输入。

## 历史 C/V 交接方案

早期 Cube 将结果写 GM workspace，再通知 Vector 读取并执行 ReLU。每组拥有独立槽位。Vector 完成对槽位的读取后发回执，Cube 收齐必要回执才覆盖槽位；事件必须匹配参与的子核数，最后一轮也要明确协议。曾因 FFTS 控制地址未初始化而出现同步时报错，Host 获取硬件同步地址后，参与侧均需按目标 SDK 初始化。

该方案适合说明所有权与握手约束；本文没有提供可运行的跨架构混合 Kernel，不应从这些文字推导完整事件编码。

## 历史优化与复验顺序

历史 dav-3510 实现在 Fixpipe 写回时做 ReLU，省去上述 GM 中转和 Vector 激活阶段。L1 使用 K 双缓冲，默认输出 tile 为 32×32、K 分块为 128，这只是原实现的配置记录，不能作为可运行模板。它是特定目标配置，不能作为所有形状和设备的最优值。

优化先比较 K 分块，再比较输出 M/N tile，最后考虑流水和写回。增大 tile 前检查 L1、L0A/B/C、UB 的容量、对齐及双份缓冲开销。双缓冲必须保护消费者最后一次读取，并覆盖启动、稳态和收尾。保留优化需同时通过精度、尾块、边界与同口径性能对照；无收益的候选回退。

历史性能数字不能当成当前设备结论，使用仓库统一测试工具在目标设备重新测量，并比较 native 的全部阶段及流水指标。
