# 临时文件与验证证据管理

需要最小诊断源、候选实现、SDK inventory、日志或 profiling 时查阅。下面是本 Skill 选择工作区的约定，复用仓库现有忽略规则，不改变公共构建/测试框架。

## 路径与用途

| 内容 | 位置与边界 |
|---|---|
| 正式 Kernel、Host、绑定、测试和 API 文档 | 仓库规范中的源码位置，需要交付，不作为临时文件清理 |
| 正式构建产物与 wheel | 由当前 setup.py/build_tools 管理，默认 build/output 等位置见构建说明，不混入手工候选文件 |
| 本地诊断和实验 | 仓库根的 `build/cce-work/<op>/<run-id>/`，不同任务和每次实验使用独立目录 |
| profiling、CSV、日志和 SDK inventory | 同一任务目录的子目录；测试通过 `--prof-dir`、`--csv-path` 指定 |
| 一次性迁移脚本或可再生成中转副本 | 使用系统临时目录中的唯一子目录，使用结束清理 |
| 远端大型结果 | 留在用户授权容器/目录的独立任务工作区；报告保留结论和可定位路径，不写入 API 文档 |

系统临时目录可这样创建，并由当前任务保留实际路径：

```bash
CCE_WORK_DIR=$(mktemp -d "${TMPDIR:-/tmp}/cce-example.XXXXXX")
```

仓库内工作区写入前用 `git check-ignore -v -- <目标路径>` 核对忽略规则。当前 `.gitignore` 的 `**/build/` 覆盖 `build/cce-work/`；`results/`、`profilings/`、任意 JSON/CSV 并不自动被忽略。公共测试工具的默认 profiling 路径是当前目录的 `profilings/`，工具不会自动删除它，需要显式选择工作区。不为此修改公共 helper 或新增仓库全局规则。

## 保存与清理

- 记录实验对应的提交/源码、形状、dtype、设备和版本、基线、命令及原始结果路径，避免报告引用已覆盖的结果。不同采样用唯一 run-id；新建 profiler 采集目录，不能混算旧 CSV。
- 任务未完成或仍需复验的证据保留；PR 描述或附件保留关键结论与必要结果。`/tmp` 可能被系统清理，不能作为长期证据存储；清理构建目录前先转存仍需保留的证据。
- 可再生成中转脚本和副本在使用结束后清理，只处理本任务明确创建的路径。禁止通过 `git clean -fdx` 或通配删除清理共享工作区。
- 原有未跟踪文件、其他会话输出和正在使用的构建目录保持原样。提交前检查状态，仅加入本任务正式文件。
- 正式源码所 include/import 的辅助文件必须进入交付，不允许依赖 `/tmp`、候选目录或个人安装目录中的源码。
